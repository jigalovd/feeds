# Секреты и межпроцессная граница

**Статус:** утверждено  
**Владелец фактов:** SecretStore, DPAPI и единый системный lock  
**Читать когда:** меняются секреты, доступ к ним или межпроцессная синхронизация  
**Связанные документы:** [карта технической документации](README.md)

## Секреты

`SecretStore` использует Windows DPAPI в области `CurrentUser` через `CryptProtectData` и `CryptUnprotectData` с запретом системного UI. Зашифрованные blobs хранятся в `%LOCALAPPDATA%\Feeds\secrets`.

Публичная граница ограничена операциями:

```text
put(ref, value)
get(ref)
delete(ref)
exists(ref)
```

Секретами являются Telegram `api_hash`, Telethon `StringSession` и ключ облачного LLM. `api_id`, endpoint и model секретами не являются. Имена файлов не содержат идентичность аккаунта или секретное значение.

Запись использует атомарную замену без plaintext-временных файлов. Секрет никогда не возвращается через `repr`, CLI, HTTP-ответ, журнал или diagnostic bundle. Machine-scope, резервное копирование секретов и перенос между Windows-профилями не поддерживаются. После удаления или потери профиля требуется повторная авторизация.

Telethon `StringSession` расшифровывается только в память. Telegram `access_hash` хранится в `StateStore` только как ограниченная техническая metadata источника либо приватного send-only получателя. Он не выходит в CLI, HTTP-ответы, логи или диагностику.

## Единый межпроцессный lock

Единственный Windows mutex называется `Local\Feeds.SystemLock`.

Полный run удерживает его до завершения. Тот же mutex используется для миграции состояния, изменения несекретной конфигурации и установки либо удаления Windows-задачи. Панель как сервер mutex не удерживает. Чтение статуса и безопасной диагностики выполняется без него.

Если новый run не может захватить mutex, он возвращает типизированный результат `run_already_active` и не создаёт отложенный запуск. `cancel_requested` записывается без mutex. Остальные конфликтующие изменяющие операции также завершаются типизированным конфликтом.

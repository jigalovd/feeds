# Продуктовая модель содержимого

**Статус:** утверждено  
**Владелец фактов:** информационные потоки, элементы, реклама, фиксация и синтез результата  
**Читать когда:** меняются правила отбора, нормализации, учёта или систематизации содержимого  
**Связанные документы:** [карта продуктовой документации](README.md)

## Информационные потоки

### Общая модель

Пользователь работает с плоским каталогом доступных информационных потоков. Для каждого потока хранится явный флаг участия в мониторинге. Пользователь включает и исключает потоки вручную через админ-панель.

Платформенные папки, списки и другие пользовательские группировки могут использоваться адаптером только для полного обхода. Они не задают выбор, фильтрацию, наследование или структуру результата: пользовательская структура может быть неполной и хаотичной.

При первоначальном обнаружении все подходящие потоки включаются по умолчанию. Повторное обнаружение выполняется только по явной команде и не является частью обычного запуска. Потоки, найденные позднее, добавляются выключенными.

### Ограничения Telegram v1

Единственным источником истины для каталога служит полный доступный аккаунту список Telegram-диалогов, дедуплицированный по стабильному peer ID.

Источниками v1 являются только публичные broadcast-каналы с username. Архивный и приглушённый статусы не влияют на участие канала.

Не являются источниками:

- приватные broadcast-каналы;
- обычные группы;
- супергруппы, включая форумные;
- личные диалоги;
- боты;
- «Избранное»;
- истории Telegram;
- настроенный канал доставки.

## Элементы содержимого

### Общая модель

Один элемент — неделимая нормализованная единица информационного потока. Она содержит доступный семантический текст, безопасные метаданные, ссылки и ссылки на происхождение. Составной платформенный объект, например медиаальбом, остаётся одним элементом.

Обработка текстоцентрична. Система ни при каких обстоятельствах:

- не скачивает, не хранит и не распознаёт бинарные вложения;
- не передаёт модели изображения, миниатюры, документы, аудио или видео;
- не открывает внешние URL для извлечения содержимого страницы.

Элемент без семантического текста включается в доставляемый результат детерминированно, без LLM-резюме. Это делает его обработку видимой пользователю и не требует передачи бинарных данных модели.

Платформенные служебные события полностью исключаются из продуктовой обработки: они не анализируются, не отображаются и не считаются содержательными элементами.

### Ограничения Telegram v1

Одна публикация — одиночное поддерживаемое Telegram-сообщение либо неделимый медиаальбом одного канала.

Семантическим текстом могут быть текст сообщения, подпись и доступные текстовые поля Telegram link preview.

К детерминированным элементам без семантического текста относятся, в частности:

- публикации только с URL без содержательного Telegram preview;
- публикации только с медиа;
- голосовые сообщения без содержательной подписи;
- любые Telegram-опросы.

Официальные Telegram sponsored messages не запрашиваются. Обычная рекламная публикация канала обрабатывается по правилам модельной классификации ниже.

## Реклама

Обычный элемент может быть признан рекламным только консервативной модельной классификацией. Детерминированные признаки служат сигналами, но сами по себе не исключают публикацию.

Анализ возвращает:

```text
content_kind: editorial | advertisement | mixed | insufficient
ad_evidence: string[]
```

К `advertisement` относится публикация, основная цель которой — коммерческое продвижение товара, услуги, курса, события или другого канала. Новости о продуктах и компаниях, сравнения цен, содержательные публикации с короткой рекламной вставкой и сомнительные случаи рекламой не считаются. `mixed` и `insufficient` остаются в основном результате.

Подтверждённые рекламные публикации не резюмируются и не показываются среди новостей. Результат содержит агрегированный счётчик:

```text
Отфильтровано рекламных публикаций: N
```

## Фиксация новых элементов и локальный прогресс

### Общая модель

Для каждого отслеживаемого потока система хранит собственный локальный cursor. Telegram unread-state и `readHistory` не используются и не изменяются.

Каждый запуск фиксирует отдельный неизменяемый batch элементов после текущего cursor до зафиксированной верхней границы. Сбор batch сам по себе не продвигает cursor.

Более новые элементы, появившиеся после фиксации batch, относятся к следующему запуску. Изменение или удаление исходного объекта после фиксации не меняет текущий результат.

Продукт не вводит лимит, позволяющий молча отбросить часть зафиксированного batch. Ограничения модели и канала доставки приводят к пакетированию и разбиению, но не к потере элементов.

Весь новый `DeliveryPlan` является границей фиксации прогресса. Пока хотя бы одно его сообщение не получило `confirmed`, cursors всех вошедших в план batches остаются прежними. После `confirmed` всех сообщений `operations` одной локальной транзакцией продвигает каждый cursor до верхней границы соответствующего batch.

Частично отправленный план сначала восстанавливается с теми же сообщениями и `random_id`; новый синтез его элементов до закрытия recovery не начинается. Отдельные per-item состояния доставки и подтверждения источника не вводятся.

### Ограничения Telegram v1

При начале сбора для каждого канала фиксируется верхняя граница Telegram message ID. Диапазон batch задаётся текущим локальным cursor и этой границей.

Действия пользователя в другом Telegram-клиенте и его unread-state не меняют локальный cursor или состав уже зафиксированного batch.

При первом включении канала начальная нижняя граница соответствует моменту снимка минус настроенный интервал. Более старая история игнорируется и не меняет Telegram read-state. После полной доставки первого плана локальный cursor продвигается обычным правилом. Та же bootstrap-политика применяется при повторном включении отключённого канала.

## Систематизация и обобщение

### Пользовательская политика

Пользователь задаёт критерии в постоянном редактируемом текстовом поле `digest_policy_prompt`. Промпт объясняет модели, что считать важным, какие аспекты выделять, какой уровень подробности использовать и какие выводы особенно интересуют пользователя.

Промпт влияет на модельную оценку, но не может отменить продуктовые инварианты:

- полноту покрытия;
- сохранение происхождения и ссылок;
- отделение фактов от модельного взгляда;
- правила рекламы и детерминированных элементов;
- запрет анализа бинарных данных;
- безопасную структурированную схему результата.

Отдельной фиксированной шкалы важности нет. Модель ранжирует элементы относительно друг друга для текущего запуска.

### Теги текущего запуска

Тематическую структуру модель создаёт заново с учётом `digest_policy_prompt` и фактического состава элементов. Для каждого содержательного элемента модель назначает один основной тег.

Теги одного запуска нормализуются, чтобы различия регистра, числа или близкие формулировки не создавали дублирующие разделы. Они не являются постоянной настройкой, не переносятся автоматически в следующий запуск и не требуют подтверждения.

Детерминированные элементы, которые модель не анализирует, помещаются системой под технический тег «Без текстового содержания».

### Содержательная карточка

Каждая содержательная карточка обязана включать:

- заголовок;
- краткое резюме переданных элементов;
- обязательный блок `model_view`;
- ссылки на все существенные исходные элементы.

Резюме содержит только факты из переданного содержимого. `model_view` является явно отделённым взглядом модели: он может содержать интерпретацию, тенденцию или возможное следствие, но только на основании содержимого текущего запуска и без добавления внешних фактов.

Если содержательного дополнительного вывода нет, блок не пропускается: в нём выводится стандартная фраза «Содержательный дополнительный вывод отсутствует».

Дополняющие, обновляющие и дублирующие элементы разных потоков могут быть объединены в одну карточку с сохранением всех существенных ссылок. При конфликте карточка явно разделяет утверждения источников, а `model_view` не выдаёт неподтверждённую версию за установленный факт.

Смысловая дедупликация выполняется только между разными потоками. Разные элементы одного потока не проверяются на смысловое или техническое дублирование и обрабатываются как самостоятельные.

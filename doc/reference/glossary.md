# Глоссарий `feeds`

**Назначение:** единые термины без введения новых правил поведения  
**При конфликте:** действует применимый [нормативный владелец](../README.md#источники-истины)

**Адаптер** — реализация внешнего порта для конкретной технологии или платформы.

**MCP-интеграция** — выбранное направление агентского интерфейса после v1; в v1 не поставляется и пока не имеет публичного контракта.

**Админ-панель** — локальный loopback-интерфейс настройки, ручного запуска и диагностики.

**Bootstrap** — первое окно после включения источника, в котором более старая история не создаёт элементы, а локальный cursor продвигается по общему правилу после успешного закрытия batch.

**Дайджест** — доставляемый структурированный результат запуска; не архитектурный модуль.

**Дедупликация** — смысловое объединение элементов разных потоков об одной новости с сохранением происхождения.

**Детерминированный элемент** — элемент без семантического текста, который не передаётся LLM, но явно учитывается в результате.

**Информационный поток (`Source`)** — подключаемая последовательность публикаций одного канала.

**Элемент содержимого (`ContentItem`)** — нормализованная неделимая единица потока без SDK-типов и бинарных данных.

**Batch фиксации (`CaptureBatch`)** — неизменяемый complete-снимок новых элементов одного потока с локальными `cursor_before` и `cursor_after`. Незавершённый `capturing` batch не используется частично.

**Локальный cursor** — последний Telegram message ID источника, закрытый приложением после полной подтверждённой доставки связанного плана либо успешной фиксации пустого batch. Внешний Telegram unread-state не участвует.

**Происхождение (`OriginReference`)** — нормализованная идентичность исходного объекта и доступная пользователю ссылка.

**Результат синтеза (`SynthesisResult`)** — полный валидный платформенно-нейтральный результат: карточки, теги, реклама, детерминированные элементы, ссылки и взгляд модели.

**Единица доставки (`DeliveryUnit`)** — группа представления одного из видов `content_card`, `advertisement_summary`, `deterministic_summary` или `warning_summary`. Одна content-unit содержит все карточки и сообщения одного тега; границей фиксации локального прогресса является весь план.

**Сообщение доставки (`DeliveryMessage`)** — неизменяемые финальные текст, entities и `random_id`, отправляемые одним внешним вызовом.

**Квитанция доставки (`DeliveryReceipt`)** — результат одного вызова отправки: `confirmed`, `unknown` или `failed`.

**План доставки (`DeliveryPlan`)** — публичный неизменяемый агрегат с минимальной адресной metadata приватного send-only получателя и упорядоченными units и сообщениями, целиком сохранённый до первой отправки. Только подтверждение всех сообщений плана разрешает продвинуть связанные локальные cursors.

**Проблема запуска (`RunProblem`)** — безопасный код, фаза, повторяемость и необязательный флаг `attention_required`.

**Пользовательская политика (`SynthesisPolicy`)** — редактируемые критерии важности, акценты и подробность в пределах инвариантов продукта.

**`model_view`** — обязательный, явно отделённый взгляд модели по данным текущего запуска.

**Порт** — интерфейс требуемой внешней возможности без привязки к библиотеке.

**Composition root** — единственное место выбора и связывания реализаций портов.

**Модульный монолит** — одно приложение с проверяемыми модульными границами.

**Тонкая точка входа** — интерфейс, который преобразует ввод и вывод, но не содержит правил запуска.

**Вертикальный срез** — небольшой исполняемый путь от триггера до наблюдаемого результата или проверенного отказа.

**Секрет** — Telegram-сессия, данные авторизации или ключ внешнего провайдера.

**CLI** — небольшой человекочитаемый операционный интерфейс для пользователя и Windows Task Scheduler с типизированными exit codes, но без публичного машинного JSON-контракта.
